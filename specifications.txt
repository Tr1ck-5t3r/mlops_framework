PROJECT SPECIFICATION: DECLARATIVE MEDALLION PIPELINE & ML ENGINE
================================================================================
Project Name: Declarative Medallion Engine & ML Delivery Delay Prediction
Tech Stack  : Python 3.10+, PySpark 3.x, Delta Lake, MLflow, Matplotlib, Pandas
Architecture: Medallion Architecture (Bronze -> Silver -> Gold) + ML + Registry

--------------------------------------------------------------------------------
1. DATA ARCHITECTURE & ETL ENGINE (runner.py)
--------------------------------------------------------------------------------
1.1 Bronze Stage (Landing & Ingestion)
    - Supports single-table or multi-table Bronze ingestion via YAML schema.
    - Ingests landed flat files matching configured file glob patterns.
    - Enriches records with lineage metadata (_ingested_at, _source_file).
    - Writes to Bronze Delta Lake with schema evolution enabled (mergeSchema).
    - Moves raw processed files into timestamped archive directories where configured.

1.2 Silver Stage (Cleansing, Validation & Quarantine)
    - Applies configurable cleansing: NA imputation, duplicate removal, NA drops.
    - Runs assertion expression checks defined in PipelineConfig.
    - Quarantines non-compliant records into a Quarantine Delta path with
      failure cause tagging (_failed_rules, _quarantined_at).
    - Computes and logs Data Quality metrics (Clean Count, Quarantine Count,
      Pass Rate %, Quarantine Ratio %).

1.3 Gold Stage (Feature Engineering)
    - Supports dynamic relational multi-table joins on configured Delta tables.
    - Applies optional post-join SQL selection and transformation expressions.
    - Supports legacy group-by + aggregation mode for backward compatibility.
    - Writes Gold Feature Store to Delta using overwrite or configured write mode.

1.4 Maintenance Stage
    - Performs automated Delta table file compaction via OPTIMIZE.
    - Conducts stale file cleanup via VACUUM with configurable retention hours.
    - Supports explicit maintenance table list or defaults to Silver/Gold targets.

--------------------------------------------------------------------------------
2. MACHINE LEARNING ENGINE (PySpark MLlib + MLflow)
--------------------------------------------------------------------------------
2.1 Pipeline Model Architecture
    - Categorical Encoding : PySpark StringIndexer (handleInvalid="keep")
    - Feature Vectorization : PySpark VectorAssembler (handleInvalid="skip")
    - Model Estimator     : GBTRegressor (Gradient-Boosted Trees)
    - Target Variable     : Actual vs. Predicted Delivery Delay Days

2.2 Model Evaluation & Observability
    - Evaluation Metrics   : Root Mean Squared Error (RMSE), MAE, R-Squared (R²)
    - Feature Importance  : Extracted from GBT model, plotted via Matplotlib,
                            logged as an MLflow artifact under charts/.
    - MLflow Logging       : Parameters, metrics, feature importance scores,
                            and full Spark PipelineModel artifact.

--------------------------------------------------------------------------------

3.2 Promotion Lifecycle

--------------------------------------------------------------------------------
6. MODEL REGISTRATION LOGGING & BATCH INFERENCE (NEW)
--------------------------------------------------------------------------------
6.1 Registration Compact Log
        - After a training run, `scripts/register_and_run_inference.py` will register
            the latest MLflow run's model into the MLflow Model Registry under the
            registered name `GBT_Delivery_Delay_Pipeline` and write a small JSON
            record to `scripts/register_compact_log.json` BEFORE starting Spark.
        - Purpose: create a concise machine-readable artifact that confirms the
            registration attempt and records `run_id`, `model_name`, `version` (if
            successful), `stage`, `timestamp`, and `error` (if any).
        - Example fields:
                - `run_id`: MLflow run identifier used to register the model
                - `model_name`: string ("GBT_Delivery_Delay_Pipeline")
                - `success`: boolean
                - `version`: registered model version (string) or null
                - `error`: error message when registration failed
                - `stage`: target alias (e.g., "staging")
                - `timestamp`: unix epoch seconds when the log was written

6.2 Batch Inference Output
        - The same script will attempt to load the registered model from the
            registry alias `models:/GBT_Delivery_Delay_Pipeline@staging` (or fallback
            to the run artifact `runs:/<run_id>/gbt_delivery_model`) and run batch
            inference on the Gold features Delta table.
        - Predictions are written as Parquet to `data/predictions/predictions_<run_id>`.
        - The Parquet output contains original Gold feature columns plus
            `predicted_delay_days` and is suitable for downstream analysis or loading
            into Delta.

6.3 How to interpret `scripts/register_compact_log.json`
        - If `success` is true and `version` is present: registration succeeded.
            Use `scripts/check_registry.py` to list versions and aliases or view the
            MLflow UI at `http://localhost:5000` (if using local MLflow server).
        - If `success` is false and `error` is set: registration failed — the
            `error` string should provide the cause (auth, duplicate name, connectivity).

6.4 Troubleshooting noisy Spark logs
        - The registration log is written before Spark is started to ensure the
            record exists even if Spark/Py4J log noise overwhelms stdout/stderr.
        - The inference script also lowers Spark/JVM log verbosity (sets root
            logger to ERROR) to reduce heartbeater noise in local runs.
